# MacDuo

把 MacBook 变成一块会随盖角折过去的屏幕：全屏截图 → 拉成上窄下宽的梯形（**底边不动**）→ 梯形
之外纯黑 → 再从顶端往下套一层逐渐减弱的高斯模糊。

合到 90° 以下时，内建显示器上的画面会：

1. **横向拉成梯形**：底边钉在屏幕底边、一动也不动；盖子越往下，顶端收得越窄。画面是被拉伸填满
   这个梯形的（整体仍然可见），不是被裁掉。
2. **梯形之外是黑色**：露出来的是盖子背后的空间，直接填黑。
3. **模糊从上往下递减**：半径在顶端拉满，到铰链端降到 0，所以底边那一侧始终是**逐像素清晰**的
   原画面；整体强度随折角增长。
4. 90° 及以上：效果完全为零，覆盖窗口收起。探针逐像素比对过，此时输出与捕获帧**完全一致**
   （0.000% 的采样点有差异），不是"接近一致"。

```
角度 90°          角度 ~67°          角度 ~45°          角度 ~22°
┌────────┐        ┌────────┐        ╱────────╲        ╱──────╲
│  清晰  │   →    │ 略模糊 │   →    │  模糊  │   →    │ 很模糊 │
└────────┘        └────────┘        └────────┘        └────────┘
   矩形              轻微收窄          明显梯形          更窄更糊
```

## 快速开始

```bash
./build.sh                    # 编译并打包出 dist/MacDuo.app
open dist/MacDuo.app          # 启动（菜单栏会出现一个角度图标）
```

首次运行需要授予**屏幕录制**权限（用来读取内建显示器的画面）：

```
系统设置 → 隐私与安全性 → 屏幕录制 → 勾选 MacDuo
```

授予后通常不需要重启应用；如果菜单里"画面捕获"仍显示未启动，点一下"开始捕获"即可。

不想真的去合盖子，就用菜单里的 **预览开合动画**：它会把捕获到的画面按一段循环动画反复折下去
再打开（开 → 合 → 停 → 开，8.6 秒一轮，两端是余弦缓动），在屏幕上直接看效果。再点一次停止。

没有 Xcode 的 Metal 离线工具链也没关系：应用会在运行时用内建的一份着色器源码现场编译（见下文
"关于着色器"）。

## 验证

```bash
./verify.sh                  # 跑运行时校验（不需 GUI）
./verify.sh /tmp/macduo-png  # 顺便导出四张效果预览图
MACDUO_PROBE_FLASH=1 ./.scratch/arm64-apple-macosx/release/MacDuoProbe
                             # 额外在内建屏上真实显示 3 秒半折状态（用合成帧，
                             # 不需要任何权限），可以直接肉眼看折叠
MACDUO_PROBE_BENCH=1 ./.scratch/arm64-apple-macosx/release/MacDuoProbe
                             # 额外按内建屏真实分辨率跑一遍性能（每像素 25 次采样）
```

性能实测（M1 Pro，3456×2234 全屏、每像素 25 次纹理采样、离屏同步等待）：

```
composite: 2.39 ms/frame — 418 fps of headroom
```

也就是说合盖动画里有大把余量；这也是"远端最强模糊"可以一路调到 200 pt 的原因。

`verify.sh` 会在离屏纹理上跑完整的管线，四张合成帧各验证一件事：

| 帧 | 图案 | 用来证明 |
| --- | --- | --- |
| measure | 棋盘渐变 + 上下两条异色横带 | 静止时画面分毫未动，折叠后糊的程度 |
| white | 纯白 | 梯形的四条边与外面的黑，逐行与公式对账 |
| edge | 左黑右白 | 每一行真实的模糊半径（10–90 过渡宽度 ÷ 2.563） |
| preview | 一张仿桌面（壁纸、菜单栏、窗口、程序坞） | 输出五张预览 PNG，用眼睛看效果 |

实测输出（M1 Pro，1280×800 合成帧，显示比例 1:1，顶端收窄量 0.35、最强模糊 72 pt、渐变 1.2）：

  row%   wanted sigma   measured sigma   detail kept

三组断言分别证明：

- **90° 时画面逐像素一致**（最坏差 0），方向也没翻；

  54 px 单调降到铰链端的 0.8 px，最后一行保留 100% 细节——也就是"底边完全清晰"。

## 它怎么工作

```
LidAngleSensor ──角度──▶ AppController ──折叠进度 0…1──▶ FrostOverlayController
   (IOKit HID)          (触发曲线 + 开合缓动)                │
                                                            ▼
CaptureEngine ──内建屏画面──▶ MetalFrostRenderer ──▶ 覆盖窗口 (NSWindow + MTKView)
(ScreenCaptureKit)            梯形拉伸 + 从上往下模糊
```

- **LidAngleSensor**：Apple VID `0x05AC` / PID `0x8104` 的 HID 节点，读 feature report 1。同一个
  VID/PID 下有好几个节点，所以逐个试读、只认能读出报告的那个。60 Hz 轮询，带平滑。
- **CaptureEngine**：`SCStream` 抓内建显示器，全分辨率 BGRA，排除自己的覆盖窗口避免自反馈，
  只在盖子进入生效区间时才启动。色彩空间显式设成 sRGB，并且**不把光标抓进画面**（光标由系统画在
  最上层，抓进来的话就会看到两个光标，其中一个还慢半拍）。
- **AppController**：角度 → 折叠进度（默认 90°→0° 线性），再叠一层时间常数 0.12 s 的指数缓动，
  把"掀盖子"这个突变补成一次连续折叠；同时管着预览动画和捕获的生命周期。
- **MetalFrostRenderer**：每帧三步——捕获帧 1:1 拷进带 mip 的工作纹理、生成 mip 链、合成。
- **FrostOverlayController**：内建屏大小的无边框窗口，进度为 0（或小到看不见）时直接 `orderOut`。

### 关于着色器

`Sources/MacDuoCore/Render/MetalFrost.metal` 只有四个函数：

- `frost_vertex`：把全屏四边形画成梯形。**只有上面两个角会动**：`scale = 顶端比例`，下面两个角
  的 scale 恒为 1，所以底边钉死。画面坐标 0…1 铺满这个梯形——是拉伸，不是裁切。
- `frost_vertex_flat`：同一个四边形，不带梯形。拷贝那一趟必须用它，否则画面会被压两次。
- `frost_copy`：把捕获帧 1:1 写进工作纹理的第 0 级 mip。坐标取自 `[[position]]` 而不是插值 uv，
  所以就算顶点的映射写反了它也不会翻面。
- `frost_fragment`：模糊。

模糊半径只跟画面纵坐标和折叠进度有关：

```
ramp   = (1 - uv.y) ^ 渐变曲线        // 顶端 1，铰链端 0
radius = 顶端最强模糊 × 进度 × ramp
```

模糊是 5×5 加权抽头核，权重 `1 : 4 : 6 : 4 : 1`（归一化到 256），**抽头间距就是这一行的半径**，
每个抽头再去 mip 链上取 `level = max(baseLod, log2(radius))` 那一级。半径小于 0.35 px 时直接
退化成一次 `level(0)` 采样——所以底边是逐像素精确的原画面，90° 时整屏也是。

`Tools/embed-shader.py` 把着色器嵌成 `EmbeddedShader.swift`（每次构建自动重新生成，不要手改）。
`MetalFrostRenderer.makeShaderLibrary` 的查找顺序是：bundle 里的 `default.metallib` → 进程默认库
→ **内嵌源码运行时编译**（默认路径，所以 `swift build` 出来的二进制也能直接用）。

## 设置

菜单栏下拉里有两个最常用的；完整参数在「设置…」窗口：

| 分组 | 参数 | 说明 |
| --- | --- | --- |
| 梯形 | 顶端收窄量 | 完全折叠时顶端相对底端的收窄比例。0.35 → 顶端剩 74%；底边永远不动 |
| 模糊 | 顶端模糊半径 | 顶端那一行的模糊半径，单位 pt；往下按曲线递减到 0 |
| | 渐变曲线 | 1 = 线性；大于 1 时靠近底边的一半保持清晰，糊集中在顶端 |
| 附加 | 远端额外压暗 / 白雾 / 保留色彩 | 默认全关：折叠完全由梯形与模糊表达 |
| 角度 | 开始生效角度 | 默认 90°：盖角到这里或更开时效果为零，画面干净 |
| | 满强度角度 | 默认 0°：盖角到这里或更合时拉满。效果区间就在这两者之间（默认就是 0–90°） |
| | 响应曲线 | 大于 1 时靠近开始生效角度那一段更平缓 |
| | 响应平滑 | 角度变化到画面跟上之间的时间常数，越大越像一段连续动画 |
| | 镜像 | 默认关：底边不动、顶端收窄。打开后改成顶端不动、底端收窄 |
| 硬件 | 角度偏移 / 角度倍率 | 读数不为 0 或方向相反时的校准 |

所有参数即时生效并存到 `UserDefaults`。**参数形状变了会带着版本号一起重置**：旧版本存下来的数值
描述的是另一套效果，留着只会误导。

### 角度与强度和参考实现的对应

参考实现的式子：`foldAngle = (180 − 滑杆值)/180 × π`，`progress = clamp(foldAngle / (π/2), 0, 1)`。

这里把"折角"定义成**离立起来还差多少**，也就是 `折角 = 开始生效角度 − 盖角`：盖角 90°（屏幕立着
正对你）时折角为 0、画面干净；盖角 0°（合上）时折角 90°、效果拉满。于是

```
progress = clamp(折角 / (π/2), 0, 1)
         = clamp((开始生效角度 − 盖角) / (开始生效角度 − 满强度角度), 0, 1)
折叠进度 = progress ^ 响应曲线
```

与参考实现逐字同形，**效果区间就是盖角 0–90°**。默认（生效 90°、满强度 0°）：

| 盖角 | 135° | 111°（常见开合角） | 90° | 80° | 60° | 45° | 30° | 15° | 0° |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 折叠进度 | 0 | 0 | 0 | 0.11 | 0.33 | 0.50 | 0.67 | 0.83 | **1** |
| 顶端宽度 | 100% | 100% | 100% | 96% | 90% | 85% | 81% | 77% | **74%** |
| 顶端模糊 | 0 pt | 0 pt | 0 pt | 8 | 24 | 36 | 48 | 60 | **72 pt** |

也就是：**平时开着盖子（90° 以上）屏幕完全是干净的**，只有压到 90° 以下才开始折，越合越强，
完全合上时拉满。

### 角度与强度和参考实现的对应

参考实现的滑杆是「设备展开角」：180° = 完全平摊（无效果），90° = 折成 90°（效果已经是满的），
再合下去一直保持满。它的式子与折角的换算是

```
参考： foldAngle = (180 − 滑杆值) / 180 × π ,  progress = clamp(foldAngle / (π/2), 0, 1)
     ⇒ progress = clamp((180 − 滑杆值) / 90, 0, 1)
```

把「滑杆值」换成「盖角」、把 180 换成可调的归零角度，就是本项目的映射：

```
progress = clamp((归零角度 − 盖角) / (归零角度 − 满强度角度), 0, 1)
折叠进度 = progress ^ 响应曲线
```

默认（满强度 90°、归零 135°）：

| 盖角 | 180° | 135° | 120° | 111°（常见开合角） | 100° | 90° | 45° | 0° |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 折叠进度 | 0 | 0 | 0.33 | 0.53 | 0.78 | **1** | **1** | **1** |

也就是说 **0–90° 这一段效果恒为满**（这是参考实现的形状：折到 90° 就已经拉满），
90°→归零角度之间才逐渐减弱，完全打开时屏幕是干净的。
想让常开角度下也一直带着效果，把归零角度拉回参考的 180° 即可。

## 兼容性 / 排错

- **传感器读不到**：2019 款 16" MacBook Pro 之后的机器才有这个传感器。M1/M2 的部分机型会以
  厂商私有接口（UsagePage `0xFF00`）暴露，本应用读不到，菜单栏会显示"传感器节点存在，但无法
  读取角度"。合盖模式（接外接显示器合上盖子）下内建屏关闭，同样无法使用。
- **画面不动 / 菜单里"画面捕获"是未启动**：检查屏幕录制权限。**每次重新 `./build.sh` 之后都要
  重新授权**——ad-hoc 签名的 cdhash 每次构建都会变，macOS 会把它当成一个新 App。授权后回到菜单
  点一下"开始捕获"即可，通常不必重启。
- **效果方向反了**：在「硬件」页把角度倍率改成 `-1`，或者用角度偏移校正零点。
- **只有内建屏受影响**：外接显示器上不会出现任何效果，这是有意的（外接屏没有铰链）。
- **效果不符合口味**：模糊、压暗、渐变形状都是分开的参数，先把「远端压暗」调小可以让画面在
  远端保留更多内容。

### 已知限制

- 想用录屏/截图工具记录效果时会录到模糊后的画面，因为覆盖窗口本身也是屏幕内容（只有本应用
  自己的捕获会排除它）。
- 空间切换、全屏 App 上的表现取决于窗口层级：覆盖窗口是 `.normal` 层级 + `canJoinAllSpaces`，
  全屏 App 可能盖在它上面。如果这对你是刚需，可以在 `FrostOverlayController` 里把
  `window.level` 调到 `.screenSaver`。

## 踩坑记录（改这个项目时值得先看）

- **捕获格式是 BGRA**。探针里所有取像素都走 `channel/red/green/blue` 这几个辅助函数——手写 byte
  偏移时漏了 2 个字节，结果把 `x=0,y=2` 读成了 `x=640,y=400`，白查了很久。
- **任何"按位置起作用"的效果都必须乘上 `progress × ramp`**。第一版里降饱和那一句写成了
  `mix(luma, color, frostSaturation)`，忘了乘行程掩码，于是**效果关闭时画面也被悄悄降了 8% 的
  饱和度**：棋盘图案的 `127/0/255` 变成 `120/4/238`。逐像素比对的断言一眼就看出来了——这也
  是"静止时画面必须逐像素一致"这条断言存在的意义。
- **`sample(sampler, uv, level(lod))` 配合 `mip_filter::linear` 是三分量插值的**：`Tools/MipLodProbe.swift`
  里放了一张第 0 级全黑、第 1 级全白的纹理，`lod = 0.25 / 0.5 / 0.75` 分别读回 `64 / 128 / 191`。
  所以半径可以连续变化而不会出现能看见的层级台阶，不必自己去混两级。
- **不要手写两套坐标映射**。拷贝那一趟用 `[[position]]` 自己算 uv，合成那一趟用插值 uv，两者
  各错各的，但错误会互相抵消（翻两次面就等于没翻）——所以"画面有没有翻"必须拿**捕获帧本身**
  去比，而不是拿另一趟渲染结果比。
- **`swift build` 与 Xcode 的 Metal 离线工具链无关**：着色器默认在运行时从内嵌源码编译，所以
  没装 MetalToolchain 也能直接跑。
- **别用 `NSLog` 打印 Swift 字符串**（会 SIGSEGV），用 `os.Logger`。
- **捕获必须按「应用」排除自己，不能按窗口列**。覆盖窗口铺满整屏、显示的就是捕获画面：
  只要它被拍进去一帧，这一帧就成了下一帧的输入，模糊与压暗逐帧累积——屏幕上会出现一层
  流动的糊、拖影和整体发灰（也就是那个"液体效果"）。而覆盖窗口在效果为零时是 `orderOut`
  的，用 `onScreenWindowsOnly: true` **根本列不到它**，排除列表就是空的。正确做法是
  `SCShareableContent(..., onScreenWindowsOnly: false)` + `excludingApplications: [自己]`。
  回归检查：`MACDUO_PROBE_CAPTURE=1` 会放一个纯红窗口占满内建屏再截一帧，中心像素必须**不是**
  红的（实测 `255 255 255`）。
- **两趟渲染不能共用同一个顶点函数**。拷贝那一趟如果也走梯形顶点，画面就会先在纹理里被压一次、
  合成时再压一次：梯形外轮廓看着是对的，画面内容却被挤了两遍、上角还会露出第一趟留下的黑块，
  模糊半径的测量也会整体失真。所以有了 `frost_vertex_flat`。**任何"进纹理"的中间趟都必须 1:1。**
- **覆盖窗口必须标记色彩空间**。渲染器是原样搬运像素、不做任何转换的，所以图层的色彩空间要和
  捕获时一致（都是 sRGB）。不标记的话 macOS 会把数值当成显示器自己的色彩空间来解释，覆盖窗口
  一出现整个屏幕就发灰——这正是"一到 90° 就立刻变灰"。
- **光标别抓进画面**（`showsCursor = false`）：覆盖窗口铺满整屏，抓进来的光标会在真光标旁边留一个
  慢半拍的影子。另外 `queueDepth` 越小越好，每一帧缓冲都是画面落后于现实的一帧。
- **角度映射别拿 90° 当零点**。参考实现是「平摊 = 0，折到 90° = 满」，所以搬到笔记本上
  应该是"盖角 ≤ 90° 恒为满、往展开方向才衰减"。第一版把 90° 当成零效果点，于是角度一大效果
  就消失——看起来就像方向反了。探针里现在有断言钉住：满强度角度及以下必须是 1.0。
- **逐行的期望值要用那一行真实的坐标**，不能用取整前的目标值：顶端附近渐变很陡，一行之差就能
  差出好几个灰阶。
